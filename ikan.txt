2️⃣ "File signature mismatch" (image 4) — ini bug beneran

Di APP/src/lib/file-validator.ts, ada dua cacat di daftar magic number:

ts
private static MAGIC_NUMBERS: Record<string, number[]> = {
  'application/pdf': [37, 80, 68, 70],
  'image/png': [137, 80, 78, 71],
  'image/jpeg': [255, 216, 255],
  'application/vnd...wordprocessingml.document': [80, 75, 76, 76], // ❌ SALAH
};

Sedangkan di App.tsx, allowedExtensions mengizinkan webp dan mp4 juga — tapi keduanya tidak ada sama sekali di MAGIC_NUMBERS. Jadi:

Upload .webp atau .mp4 → selalu gagal, karena signature-nya tidak pernah dicek/didaftarkan sama sekali.
Upload .docx → selalu gagal juga, karena byte signature ZIP yang benar itu PK\x03\x04 = [80, 75, 3, 4], bukan [80, 75, 76, 76] ("PKLL" — kelihatannya salah ketik).
verifySignature() juga cuma baca 8 byte pertama file — kurang untuk WEBP, karena signature WEBP ada di offset 8-11 (RIFF....WEBP), dan MP4 signature (ftyp) ada di offset 4-7, bukan offset 0.

Jadi kemungkinan besar file yang kamu upload di screenshot itu .docx, .webp, atau .mp4 — ketiganya memang dijamin gagal validasi dengan kode saat ini.

Perbaikan
ts
export interface ValidationResult {
  isValid: boolean;
  error?: string;
}

export interface FileValidatorConfig {
  maxSizeMB: number;
  allowedMimeTypes: string[];
  allowedExtensions: string[];
}

interface SignatureRule {
  offset: number;
  bytes: number[];
}

export class FileValidator {
  // Signature per-extension, karena beberapa format punya offset ≠ 0
  private static SIGNATURES: Record<string, SignatureRule[]> = {
    pdf: [{ offset: 0, bytes: [0x25, 0x50, 0x44, 0x46] }], // %PDF
    png: [{ offset: 0, bytes: [0x89, 0x50, 0x4e, 0x47] }], // .PNG
    jpg: [{ offset: 0, bytes: [0xff, 0xd8, 0xff] }],
    jpeg: [{ offset: 0, bytes: [0xff, 0xd8, 0xff] }],
    docx: [{ offset: 0, bytes: [0x50, 0x4b, 0x03, 0x04] }], // PK\x03\x04 (ZIP)
    webp: [
      { offset: 0, bytes: [0x52, 0x49, 0x46, 0x46] }, // RIFF
      { offset: 8, bytes: [0x57, 0x45, 0x42, 0x50] }, // WEBP
    ],
    mp4: [{ offset: 4, bytes: [0x66, 0x74, 0x79, 0x70] }], // ftyp (offset 4!)
  };

  static async validate(
    file: File,
    config: FileValidatorConfig
  ): Promise<ValidationResult> {
    if (file.size > config.maxSizeMB * 1024 * 1024) {
      return {
        isValid: false,
        error: `File size exceeds limit of ${config.maxSizeMB}MB`,
      };
    }

    const extension = file.name.split('.').pop()?.toLowerCase();
    if (!extension || !config.allowedExtensions.includes(extension)) {
      return {
        isValid: false,
        error: `Extension .${extension} is not supported`,
      };
    }

    if (!config.allowedMimeTypes.includes(file.type)) {
      if (file.type !== 'application/octet-stream') {
        return {
          isValid: false,
          error: `MIME type ${file.type} is not supported`,
        };
      }
    }

    const isValidSignature = await this.verifySignature(file, extension);
    if (!isValidSignature) {
      return {
        isValid: false,
        error:
          'File signature mismatch. The file content does not match its extension.',
      };
    }

    return { isValid: true };
  }

  private static async verifySignature(
    file: File,
    extension: string
  ): Promise<boolean> {
    const rules = this.SIGNATURES[extension];
    if (!rules) return false; // extension tak dikenal → tolak, jangan diam-diam lolos

    // Ambil cukup byte untuk offset terjauh + panjang signature-nya
    const maxNeeded = Math.max(...rules.map((r) => r.offset + r.bytes.length));
    const header = await file.slice(0, maxNeeded).arrayBuffer();
    const bytes = new Uint8Array(header);

    // Semua rule harus cocok (mis. WEBP butuh RIFF di offset 0 DAN WEBP di offset 8)
    return rules.every((rule) =>
      rule.bytes.every((byte, i) => bytes[rule.offset + i] === byte)
    );
  }
}

Perubahan intinya:

DOCX diperbaiki ke PK\x03\x04.
WEBP dan MP4 ditambahkan (dengan offset yang benar).
Validasi sekarang dicek spesifik sesuai ekstensi file yang diklaim, bukan "cocok dengan sembarang signature yang terdaftar" — versi lama itu juga celah keamanan kecil, karena file .pdf palsu berisi byte JPEG bisa lolos selama cocok dengan magic number apa saja di daftar.
